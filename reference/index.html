Strings & literals

Turn an encoded or calculated value back into the real thing.

String decoding

stringDecoding

Puts the real text back into your code.

Obfuscators move every piece of text into one big lookup table, so "getElementById" arrives as something like _0x3f2a(0x1b). This finds that table and the function that reads from it, works out what each call returns, and writes the text back where it belongs. Once nothing refers to the table any more, the table is deleted too.

Literal simplification

literalSimplification

Works out values that were never going to change.

Obfuscators write constants as work: 0x2 * 0x3 + 0x1 instead of 7, 'un' + 'weave' instead of 'jsrift', !![] instead of true. Anything whose result is fixed is calculated once, here, and replaced by the result. It happens in three places: before anything else, again on code that came out of a packed file after that first sweep had already finished, and again later, because decoding text keeps producing more of these.

Property normalization

propertyNormalization

Writes property access the way you would write it.

Obfuscated code reaches properties through strings: config['retry']['limit'] rather than config.retry.limit. Where the key is a plain name, it is rewritten with a dot. Keys that cannot be written that way - 'on-error', '2fa' - are left alone, and so are __proto__, constructor and prototype, where the bracket form can be doing real work.

Control flow analysis

controlFlowAnalysis

Puts scrambled code back in the order it runs.

Some obfuscators chop a function into numbered chunks and wrap them in a loop with a switch, so the code jumps around instead of reading top to bottom. The real order is kept in a list nearby - '3|0|4|1|2' means chunk 3 runs first. This reads that list, puts the chunks back in order, and removes the loop.

A function chopped into numbered chunks

Statement recovery

statementRecovery

Turns packed one-liners back into ordinary statements.

Obfuscators squeeze several statements into one expression: a && b() in place of an if, commas in place of separate lines, a ? b() : c() in place of if/else. Where the value of that expression is thrown away anyway, the ordinary form means exactly the same thing, so it is written back that way. Loop bodies that were left without braces get them.

Function unwrapping

functionUnwrapping

Replaces go-between functions with what they do.

Obfuscators route ordinary work through extra functions and lookup objects, so base * tax arrives as _0x3a2f['nPzL'](base, tax). Where a wrapper does nothing but hand its arguments to a single expression, that expression is written at the place it was called and the wrapper is deleted. A wrapper is only expanded when the arguments line up and moving them cannot change the order things happen in.

Dead code removal

deadCodeRemoval

Removes code that never runs.

Obfuscators pad files with branches that can never be true - if ('LWmvB' === 'pxKtR') - and with variables nothing ever reads. This works out which branches can actually happen, keeps those, and deletes the rest along with anything left over that nothing points at.

Anti-tamper removal

antiTamperRemoval

Removes the traps that fight being inspected.

Protected files carry code whose only job is to stop you reading them: loops that trip the debugger over and over, checks that hang the program once the source has been reformatted, and code that quietly switches console.log off. This recognises those three shapes and removes each one whole - the trap, the guard around it and the line that starts it. If anything else in the file still uses a piece of that machinery, it is left in place instead.

Variable renaming

variableRenaming

Names variables after what they are used for.

Obfuscated code calls everything _0x4d28ce. This looks at what each variable is actually used for - what it is passed to and in which position, what is read off it, what is assigned to it - and takes a name from that: the value handed to fetch first becomes url. A guess that is not strong enough is left alone, and a new name is only used where it cannot collide with another variable of the same name.

Module unwrapping

moduleUnwrapping

Opens packed files and bundles into readable code.

Some files are not really source. They are one eval call with the whole program compressed inside, one Function("...") call holding the program as text, or a bundler's map of numbered modules. The first two are opened without being run, again and again while there are layers left; the third is split so each module becomes a normal named function you can read.

A whole file packed into one eval call

JSX restoration

jsxRestoration

Turns compiled React calls back into JSX.

A build tool turns <td>{label}</td> into _jsx('td', { children: label }). This turns those calls back into tags - but only where the two are exactly the same thing. _jsx(foo, {}) is not <foo />, because the tag would ask React for an HTML element called foo instead of using your variable, so a call it cannot prove is left as a call.
